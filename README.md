# ATR 面单系统

尾程面单管理系统：对接 **ShipBest OMS**，按我们的成本加价给客户报价、出 4×6 面单。包含**后台管理**和**客户自助端**，带客户钱包（预付 / 月结）、批量下单、官方账单补差、对账单。

## 一、马上试用（演示模式）

演示模式用**模拟接口**，不会真实下单、不会扣 ShipBest 余额。需要 Node.js 20 或以上版本。

```bash
npm install
npm run demo
```

启动后打开：

| 入口 | 地址 | 账号 |
|---|---|---|
| 后台 | http://localhost:3000/ | 密码 `admin1234` |
| 客户端 | http://localhost:3000/portal | `demo@example.com` / `demo1234`（预付客户，余额 200） |
| 客户端 | 同上 | `monthly@example.com` / `demo1234`（月结客户，信用额度 500，加价 8%） |

数据保存在 `./data-demo`，删除这个目录再运行就会重置。

**建议的测试流程：**

1. **客户端**用 demo@example.com 登录 → “下单”：填收件人和包裹，查询运费，出单，打印面单。可以看到客户只看得到运费，看不到成本和利润。
2. **客户端** → “批量下单”：下载模板，不用修改直接上传（模板里有 3 行示例 = 2 个订单），确认下单，合并打印。
3. **客户端** → “账户与账单”：查看扣款流水、余额和对账单。
4. **客户端**打开一张已出单的面单 → “申请取消”。
5. **后台**登录 → “面单记录”找到这张单 → “确认已取消”，客户余额自动退回（扣 10% 手续费）。
6. **后台** → “客户” → 管理：充值、设置信用额度、开通/重置客户登录密码、查看流水。
7. **后台** → “补差导入”：上传 ShipBest 的补差表，按客户预览，导入后自动从客户余额扣补差，客户可以在“补差明细”里看到并下载。
8. **后台** → “财务”：所有客户的余额和欠款。

## 二、功能

### 后台（员工使用）

- **报价出单**：一次试算所有启用渠道，显示 ShipBest 原价、我们的成本（优惠后总运费）、客户价和利润；可以替任意客户出单，从该客户余额扣款。
- **加价规则**：`客户价 = max(成本 × (1 + 加价%) + 固定加价, 成本 + 最低利润)`，再按步长向上取整。三级设置：**客户专属 > 渠道 > 全局默认**，按字段逐项覆盖。
- **批量下单**：上传 Excel，后台逐单报价（指定渠道或每单自动选最便宜），确认后逐单下单；余额不足自动暂停，充值后可继续；面单合并成一个 PDF 打印。
- **客户与钱包**：
  - 预付客户：先充值后下单；月结客户：设置信用额度，余额可以透支到负的额度。
  - 出单扣款、取消退款、补差扣/退都会自动记账；支持手动充值和调账，每笔都有流水。
  - 给客户开通客户端登录、设置或重置密码（密码只显示一次）、设置客户默认寄件地址。
- **取消**：先尝试接口取消；已出面单的需要在 OMS 找 ShipBest 人工取消，完成后在系统里“确认已取消”，自动按设置的比例扣手续费并把剩余部分退回客户余额。
- **官方账单补差（多退少补）**：上传 ShipBest 的补差表（.xlsx / .csv），自动识别列，按运单号 / 客户单号对应到面单和客户。
  - 默认**按该单的加价比例转嫁**：补收 0.06、加价 5% → 客户补 0.07（补收向上取到分，退款舍去零头）。也可以改成按原金额转嫁或不转嫁。
  - 补差说明自动写成“重量调整：预报 25 oz → 结算 32.74 oz（超出 7.74 oz）· 实重 · 分区”。
  - 防止重复导入（按表格内容判断）；没对上的行可以手动关联；整批可以撤销（钱包扣款一起撤回）。
  - 按客户导出补差明细，不含成本、费用和服务商账户名。
- **对账与财务**：面单记录筛选和导出、利润汇总、客户对账单、财务总览（客户预存和欠款）、流水导出。

### 客户端（客户自己登录，地址 `/portal`）

- 单个下单、批量下单（Excel 模板）、合并打印面单。
- 只显示客户价，**看不到我们的成本、利润、加价规则和服务商的内部信息**。
- 我的面单（筛选、导出、勾选合并打印）、面单详情、申请取消。
- 账户余额、流水、对账单下载；补差明细和下载（含重量差说明）。
- 修改默认寄件地址和密码。
- 安全：密码加密存储；连续输错 10 次锁定 15 分钟；修改或重置密码后旧登录失效；客户之间数据完全隔离。

## 三、部署

数据（SQLite 数据库和面单文件）存在 `DATA_DIR` 目录里，需要一台有持久磁盘的服务器或 VPS，**请定期备份这个目录**。

### 方式 A：Docker（推荐）

```bash
cp .env.example .env      # 填写配置，见下表
docker compose up -d --build
```

打开 `http://服务器IP:3000`（后台）和 `http://服务器IP:3000/portal`（客户端）。正式使用时建议加一个域名，并用 Nginx 或 Caddy 配 HTTPS。

### 方式 B：直接用 Node.js

```bash
npm install
cp .env.example .env.local
npm run build
npm start            # 默认端口 3000，可以配合 pm2 / systemd 常驻
```

### 环境变量

| 变量 | 说明 |
|---|---|
| `SHIPBEST_API_ID` / `SHIPBEST_ACCESS_TOKEN` | OMS 后台“API 配置”里的 ID 和 Token |
| `SHIPBEST_BASE_URL` | 默认 `https://oms.shipbest.com` |
| `SHIPBEST_MOCK` | `1` 使用模拟接口（测试用），正式环境为 `0` |
| `ADMIN_PASSWORD` | 后台登录密码 |
| `SESSION_SECRET` | 登录会话签名密钥，至少 16 位随机字符串 |
| `DATA_DIR` | 数据目录，默认 `./data` |
| `COOKIE_SECURE` | 不填则自动判断；配了 HTTPS 可以填 `1` |
| `DEMO_SEED` | `1` 时首次启动创建演示数据，正式环境不要开 |

### 正式上线步骤

1. 配好环境变量（真实的 API ID / Token，`SHIPBEST_MOCK=0`），启动。
2. 后台 → **设置**：点“测试连接”，再点“同步渠道”，勾选要开放给客户的渠道；填写全局加价、默认寄件地址（发货仓）、客户端显示的公司名称和客服联系方式。
3. 后台 → **客户**：新增客户 → 设置加价（可选）、信用额度 → 开通登录并设置密码 → 充值。
4. 把 `https://你的域名/portal` 和账号密码发给客户。
5. 先用一个真实包裹出一单，确认面单和运单号都正常。（真实出单会扣 OMS 余额。）

ShipBest 的 OMS 余额仍然在 OMS 后台查看（接口没有余额查询）。OMS 余额不足时出单会失败，客户端提示“系统繁忙，请联系客服”，后台显示具体原因。

## 四、ShipBest 接口说明

所有接口都是 POST，参数用 JSON 放在请求体里。请求头要带 `apiId`、`accessToken`、`timestamp`（毫秒）、`nonce`、`sign`。

签名方法：把 `accessToken, apiId, method=post, nonce, timestamp, url=接口路径` 这 6 项按名字排序，用 `&` 连接，再用 accessToken 作密钥做 HmacSHA256，输出十六进制。实现见 `src/lib/shipbest/sign.ts`。

| 接口 | 路径 | 系统中的用途 |
|---|---|---|
| 授权校验 | `/api/oauth/verify` | 设置页“测试连接” |
| 物流产品 | `/api/logistics/getProducts` | 同步渠道 |
| 运费试算 | `/api/logistics/trialOrderPrice` | 报价（按渠道 code 逐个试算：不传 code 时实测只返回一个渠道，且返回结果里不带 code） |
| 创建订单 | `/api/order/create` | 出单，`customNo` 由系统生成（格式 `ATR` + 日期 + 随机串） |
| 订单详情 | `/api/order/detail` | 取状态、运单号、`labelUrl`、实扣 `feePrice` |
| 订单取消 | `/api/order/cancel` | 申请取消 |

ShipBest 订单状态：1 草稿、2 待出单、3 异常、4 已打单、6 已取消。

### 实测结果（2026-09，用正式账号，只做了只读调用）

- 签名按上面的方法计算，`/api/oauth/verify` 校验通过。（文档里的示例签名 `9bc08ba7…` 本身和示例参数对不上，可以忽略。）
- 试算返回里有两个文档没写的字段：`zone`（分区，例如 `zone6`）和 `errorMsg`（该渠道不可用的原因，例如“邮编不通邮”）。系统会把分区记到每一单上，方便核对补差。
- ShipBest 说明：系统扣费是预报价格，官方账单出来后按重量或分区差异多退少补，会提供补差表格。

### 待和 ShipBest 确认的问题
- 创建订单接口的返回内容（文档里是 `{}`）。目前系统按“异步出单、轮询订单详情”来处理。
- `declaredUnitPrice` 文档写的是整数类型，小数申报价会不会被截断？
- 接口调用频率的具体上限（超出时返回错误码 11005）。

## 开发

```bash
npm test        # 单元测试 + 模拟模式完整流程测试（出单、取消、补差、钱包、批量下单）
```

目录结构：

```
src/lib/shipbest/     ShipBest 签名、接口客户端（真实 / 模拟）
src/lib/pricing.ts    加价计算
src/lib/db.ts         SQLite 表结构和数据访问
src/lib/ledger.ts     客户钱包流水
src/lib/service.ts    报价、出单、刷新状态、取消
src/lib/batch.ts      批量下单
src/lib/adjustments.ts、sheetGuess.ts  补差导入
src/lib/portal.ts     客户端可见的数据（过滤成本等内部信息）
src/app/(admin)/      后台页面
src/app/portal/       客户端页面
```
